# 数据库只读分析

对一次委派负责完整分析生命周期。除非上级明确限定了可独立验收的子目标，不得只完成结构
探查、部分指标或报告章节就返回。本 Skill 不假定固定业务指标，不负责数据库管理、写入或
索引调优。

## 阶段一：理解任务并规划

1. 确认业务问题、指标口径、时间范围、分析维度、筛选条件和期望产物。
2. 复杂任务立即用 `write_todos` 建立“结构探查、查询、验证、分析、输出”计划，并随执行
   更新状态。
3. 缺少会影响正确性的定义时停止分析，最终返回 `needs_input`，并在 `required_inputs` 中
   清楚列出缺失信息，不得自行假设。

## 阶段二：确认数据库结构

1. 先调用 `database_list_schemas`，再用 `database_list_objects` 查找候选表或视图。
2. 对实际使用的对象调用 `database_get_object_details`，核对字段、类型、主键、外键和约束。
3. 不根据相似字段名猜测关联；约束缺失时用小范围查询验证唯一性、覆盖率和关联方向。

## 阶段三：查询与深度分析

1. 先用 `database_query_preview` 检查计数、日期范围、空值和基数，再执行正式聚合查询。
2. 明确输入表、连接条件、筛选规则、指标公式和分组粒度，不把大表完整放进模型上下文。
3. 优先让 PostgreSQL 过滤、连接和聚合；需要进一步统计或制图时，用
   `database_query_to_file` 写入 `/workspace/database/`，任务脚本写入 `/workspace/scripts/`，
   最终产物写入 `/workspace/output/`。
4. 按任务需要编写并执行 `/workspace/scripts/analyze_database_<task>.py`，根据真实错误修正。

## 阶段四：验证与报告

1. 核对主键唯一性、重复值、空值、时间范围、单位币种、连接放大、未匹配记录和汇总总计。
2. 验证失败时不得给出确定性结论；工具的语法、字段、权限等确定性错误不得原样重试。
3. 查询结果超限时先聚合、过滤或拆分，不把截断数据当作完整数据。
4. 简单查询可以只生成必要产物；复杂任务必须生成图表、分析摘要和主 Markdown 报告。上级未
   指定主报告路径时使用 `/workspace/output/final_report.md`。
5. 主报告说明指标定义、关键 SQL、验证结果、数据局限、结论依据和产物索引；辅助产物按需
   使用 CSV、JSON 和 PNG。图表放在主报告同目录或子目录，必须用相对于主报告的路径嵌入
   本次生成的每一张 PNG，不能只列出文件名或绝对路径。
6. 完成前用文件工具核验主报告的全部图片引用及所有声明产物存在，随后仅按 data-analyst 系统提示词返回
   JSON 文本，并在 `artifacts` 中列出真实路径。

## 注意事项

- 只允许单条 `SELECT` 或 `WITH` 查询，不执行写入、DDL、数据库管理、锁表或 Shell 数据库命令。
- 不生成 PDF，不调用下载或用户交互工具；需要补充信息时只返回 `needs_input`。
- 不在本 Skill 中写死销售、采购、财务等业务规则，具体口径来自上级委派。
