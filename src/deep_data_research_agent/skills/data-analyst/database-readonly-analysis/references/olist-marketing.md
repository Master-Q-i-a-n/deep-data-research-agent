# Olist 商家招商与签约后表现

用于 `olist.marketing_qualified_leads` 和 `olist.closed_deals` 的商家招商分析，以及它们
与电商卖家的交叉分析。招商对象是拟入驻商家，不是 `customers` 中的电商消费者。

## 可回答的问题与数据粒度

| 问题 | 主要数据 | 分析粒度 |
| --- | --- | --- |
| 来源渠道、落地页、首次联系时间的线索分布 | `marketing_qualified_leads` | `mql_id` |
| 样本内已观测签约比例及签约耗时 | 线索表与 `closed_deals` | 同一线索群组及其签约结果 |
| 已签约商家的行业、类型、画像及申报属性 | `closed_deals` | 成功签约记录，需核验商家是否重复 |
| SDR、SR 的已签约数量与耗时分布 | `closed_deals`，耗时需关联线索表 | 已成功签约样本 |
| 签约后首次观测订单、窗口销售和商品表现 | `closed_deals`、`sellers`、`order_items`、`orders` | 签约商家及其商品明细 |

## 关联与样本边界

- 以线索表为基表，通过 `mql_id` 左连接 `closed_deals`。分母应在连接电商卖家前确定，
  不能内连接后把“所有招商线索”缩成“已签约且匹配到电商样本的商家”。
- `closed_deals.seller_id → sellers.seller_id → order_items.seller_id` 是跨样本连接路径。
  公开招商和电商样本覆盖不完全，不能因未匹配就删除签约记录或把它们认定为无经营商家。
- 查询时重新核验线索、签约记录、商家标识的唯一性及各步匹配率；不要假定每个商家永远
  只对应一条签约记录。出现重复时先明确签约事件与商家归属，再合并电商金额。
- 线索中未匹配到成功签约，只能称“样本内未观测到签约”，不是失败、流失或拒绝。
  数据没有完整销售阶段与失败原因，不能构造逐阶段销售漏斗。

## 转化与耗时口径

- **样本内签约比例**：同一首次联系群组中，在指定截止日或窗口内观测到成功签约的
  不同 `mql_id` 数，除以该群组不同线索数。明确起止日期、分组、有效记录和截止日。
  不用“本月签约数 / 本月新线索数”替代同群组转化率，签约可能来自更早线索。
- **固定窗口转化**：按委派要求确定首次联系后多少天算成功，并只比较具有足够后续
  观测期的群组。最新签约日期可帮助识别数据边界，但不能单独证明此前事件被完整采集；
  不能把窗口尚未结束的线索按失败处理。
- **签约耗时**：`won_date` 与 `first_contact_date` 的差，仅代表已成功签约样本。
  首次联系只有日期，不能声称小时级精度；需统一日期或近似天数的计算方式。
  存在签约早于首次联系的原始异常，报告数量并单独处理，不取绝对值、改写或隐藏。
- **渠道对比**：`origin` 是数据中的来源分类，`landing_page_id` 是匿名落地页标识。
  缺失来源与字符串 `unknown` 分开；小样本组展示分母。没有完整接触序列，不能推断
  最后触点、多触点归因或某渠道对签约的因果贡献。
- **属性与人员比较**：行业、商家类型、画像、`sdr_id`、`sr_id` 等来自成功签约表，
  没有对应的全部未签约线索分配信息。可分析已签约构成和耗时，不能用这些字段直接
  计算行业转化率、销售人员胜率或销售人员接手的全部线索数量。

## 签约商家属性

- `business_segment` 是商家行业，不能直接当成 `products` 的商品品类。
- `lead_behaviour_profile` 可能包含多个逗号分隔标签。拆成标签时按线索或商家去重，
  声明多标签占比可能超过 100%；不能拆行后重复累计签约数或销售金额。
- `has_company`、`has_gtin` 的 NULL 不是 false；分析这类属性前报告缺失比例。
- `average_stock` 是区间或类别，不是精确库存；申报目录规模不是平台实际上架商品数。
- `declared_monthly_revenue` 是申报月收入，不是 Olist 订单业绩。大量零值的含义不能
  自动判断为真实零收入，也不能统一改成 NULL；报告零值占比，正值子样本分析须说明筛选。
  未核实币种和收入范围前，不能将它与平台商品金额直接相除称为平台渗透率。

## 签约后电商业绩

需要计算商品金额、订单数或支付金额时，读取
[销售参考的指标口径](olist-commerce.md#需要明确的指标口径)，避免另造一套销售定义。

1. 明确签约日期群组、订单状态、订单事件时间与观察窗口。窗口长度来自委派；后续观测
   不足的商家单列，不能把观察期不同的累计金额直接排名。
2. 由签约商家关联 `order_items.seller_id`，再接 `orders.order_id`，按已确认的时间精度
   筛选签约后的订单。先核验是否存在早于签约的订单，单列解释而非自动归为签约贡献。
3. 卖家商品金额按其明细求和，卖家订单数计不同 `order_id`。多卖家订单不能将整单
   支付总额归给每个卖家；招商归因所需的分摊不能从字段名自行推导。
4. 分别报告：签约记录数、不同签约商家数、匹配到卖家样本的商家数、观察窗口充分的
   商家数、窗口内有符合条件订单的商家数。显示各分母，避免只报告有交易子样本。
5. 对未匹配商家标为“电商样本未覆盖”；已匹配但窗口内无订单标为“窗口内未观测到订单”。
   后者可在明确的样本统计口径中计零，前者不能据此推断真实业绩为零。
6. 首单时间只能称“样本内首次观测到的签约后订单时间”。按渠道汇总后续业绩只能描述
   匹配样本中的关联，不能证明招商带来的增量收入或真实商家终身价值。

## 针对本主题的验证与边界

- 分渠道签约数、线索数应回到同一群组的总体；跨电商样本连接不应改变此前的招商分母。
- 对照每一连接步骤的未匹配数和重复数；明细金额在合并渠道、标签、销售人员后不能被重复累计。
- 签约和电商数据分别核验日期范围、异常和观察截止日，不能拿两张表各自最大的日期直接
  当作所有商家都有完整业务记录的保证。
- 没有广告投入、获客费用或销售人力成本，不能计算真实 ROI、ROAS 或 CAC；没有失败
  线索全过程，不能补造流失原因或销售阶段。结论限于公开样本，不能外推为 Olist 全公司的经营指标。
