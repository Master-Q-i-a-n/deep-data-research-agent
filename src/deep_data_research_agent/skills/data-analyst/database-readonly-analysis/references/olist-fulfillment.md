# Olist 履约与消费体验

用于配送时效、运费、订单评价、卖家履约及地理分布。销售金额与消费者口径需要时读取
[olist-commerce.md](olist-commerce.md)，不因涉及订单而默认加载全部参考。

## 可回答的问题与数据粒度

| 问题 | 主要数据 | 分析粒度 |
| --- | --- | --- |
| 交运、运输、整体配送耗时及延迟 | `orders` | 一订单一组时间事件 |
| 运费负担与重量、体积、地域的关系 | `order_items`、`products`，按需关联客户和卖家地址 | 商品明细或先聚合到订单 |
| 评分分布、延迟与低分的关系 | `order_reviews`、`orders` | 评价记录或按明示规则归并到订单 |
| 负面体验主题与文本反馈 | `order_reviews` 的标题、正文、评分 | 实际有文本的评价样本 |
| 卖家参与订单的履约表现 | `order_items`、`sellers`、`orders` | 去重的订单—卖家关系 |
| 州际分布与近似运输距离 | 客户和卖家地址、`geolocation` | 邮编前缀位置或订单—卖家组合 |

## 时间口径

先确定样本状态、按下单还是送达时间选取样本、耗时单位以及缺失事件的处理。源时间未
明确时区时，保持原始时间含义，不擅自换算为用户当地时间。

| 候选指标 | 时间差 | 解释限制 |
| --- | --- | --- |
| 付款获批等待 | `order_approved_at - order_purchase_timestamp` | 不代表会计入账耗时 |
| 获批到交运 | `order_delivered_carrier_date - order_approved_at` | 订单级近似过程，不能分解每个卖家的打包耗时 |
| 交运到送达 | `order_delivered_customer_date - order_delivered_carrier_date` | 不是物流轨迹或单包裹时效 |
| 下单到送达 | `order_delivered_customer_date - order_purchase_timestamp` | 只对具有所需事件的订单定义 |
| 预计日期偏差 | 实际送达日期与 `order_estimated_delivery_date` 比较 | 需约定按自然日还是精确时间比较 |

- 预计送达字段常体现日期语义。采用自然日口径时先统一为日期，不能因为实际在预计当天
  下午送达、预计值为零点，就算成延迟；按小时计算需要明确支持该精度的承诺时间。
- 延迟率明确分母，例如“有预计日期且已实际送达的有效订单”；不能把未送达、时间缺失
  或时间倒置的订单自动计为准时。排除数量单列，阈值与统计区间需说明。
- 耗时可按问题报告中位数、分位数或均值；负耗时、零耗时与长尾分别核验，不静默取绝对值。
- `shipping_limit_date` 是明细的交运截止时间，实际交运时间在订单级。多卖家订单不能
  直接据此精确判责到单个卖家。历史快照中的未送达订单也不能以今天为截止日计算超时。

## 评价与文本

- 先检查每订单评价数及 `review_id` 的重复情况，不能假定一订单一评价。若输出订单级
  评分，需要明确取最新有效回复、汇总或保留多条的规则；“最新”使用回复时间并处理并列。
- 评价应在关联商品明细之前归并到目标粒度，否则多件商品会重复加权同一个订单的评价。
- 低分阈值与分母需声明；无评价不是零分。评价覆盖率与有文本比例单独报告，以区分
  “所有订单”“有评分订单”和“实际写了评价正文的人群”。
- 标题和正文主要是葡萄牙语，可按任务做主题归纳或情感分析；报告文本样本量、抽样方法
  和分类方式，用少量原文核验主题。评分、文本情绪与商品质量不能直接等同。
- `review_creation_date` 是调查创建或发送时间，用户反馈的时间优先看
  `review_answer_timestamp`；时间为空、重复回复或截断观察窗口须单列。
- 配送延迟与低分的关系属于观察性关联；商品、卖家、地区等混杂因素使相关性不能直接解释为因果。

## 卖家、运费与地理关联

- 先把 `order_items` 压到所需的 `(order_id, seller_id)`，再统计卖家参与订单的时效。
  多卖家订单的送达和评分是共享的订单结果，只能表述为“该卖家参与订单的表现”。
  单卖家订单可作为补充分析，但仍不是卖家独立责任的证据。
- 运费来自明细 `freight_value`。运费率须明确使用“总运费 / 总商品金额”还是
  “各订单运费率的平均值”；零商品金额需单列，不能除零或默默丢弃。
- 商品重量与尺寸按数据库注明的单位使用；缺失、非正值及异常值影响每公斤运费和体积分析。
  商品尺寸不代表实际包裹尺寸，多个明细也不代表多个独立包裹。
- `geolocation` 的邮编前缀不是唯一键。先检查一前缀多点和坐标异常，再按说明的规则
  生成一前缀一代表位置后关联；本地 `geolocation_id` 不能用于连接客户或卖家。
- 客户、卖家的邮编前缀与地理表按同一类型连接，展示补足五位；城市名称可能有拼写差异。
  仅按州分析时直接使用地址州字段即可，无需连接百万行地理表。
- 经纬度距离只是邮编区域代表点间的近似直线距离，不是实际运输里程。涉及多卖家订单时
  保留订单—卖家粒度，不能任选一个卖家代表整单路线。

## 针对本主题的验证与边界

- 核验时间事件的缺失率、先后顺序和有效样本数；比较地区或卖家时展示分母，小样本排名
  不能直接视为稳定的服务质量差异。
- 每次连接评价、商品和地理数据后，对照目标粒度记录数与运费总额，避免对评分和耗时重复加权。
- 报告地理位置、评分或实际送达时间未覆盖的订单数量；末期订单可能还没有完整结果。
- 本数据缺少仓库库存、采购单、实时物流节点、退货及售后工单，不能给出精确补货计划、
  单包裹追踪或完整售后处理效率。`average_stock` 招商字段也不能补足这些业务事实。
