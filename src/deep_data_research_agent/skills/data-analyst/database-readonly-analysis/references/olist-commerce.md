# Olist 销售与客户经营

用于消费者订单、销售结构、复购分群和支付分析。这里的客户指电商消费者；商家招商分析
见 [olist-marketing.md](olist-marketing.md)。以下表名位于 `olist` schema，关联关系需按主 Skill 核验。

## 可回答的问题与数据粒度

| 问题 | 主要数据 | 分析粒度 |
| --- | --- | --- |
| 订单及商品金额的趋势、客单价 | `orders`、`order_items` | 先得到一行一订单，再按时间汇总 |
| 消费者复购、RFM、首购群组表现 | 上述表与 `customers` | `customer_unique_id`，消费事件为去重订单 |
| 商品、品类、卖家销售贡献及集中度 | `order_items`、`products`、`category_translation`、`sellers`，结合 `orders` 筛选 | 商品明细；订单数另行去重 |
| 支付方式、分期与支付金额结构 | `order_payments`、`orders` | 支付记录或订单，按问题选择 |
| 州、城市的订单与消费分布 | `orders`、`customers`，按需关联订单金额 | 订单对应的客户地址；卖家所在地另算 |

## 关联与汇总路径

- `orders.customer_id → customers.customer_id`；跨订单归并消费者用
  `customers.customer_unique_id`，不能直接数 `customer_id` 当独立消费者。
- `order_items.order_id → orders.order_id`，明细键为 `(order_id, order_item_id)`；
  `product_id → products.product_id`，`seller_id → sellers.seller_id`。
- `products.product_category_name → category_translation.product_category_name`；
  未匹配翻译时保留原品类，原品类缺失时单列缺失组，不因翻译缺失丢弃金额。
- `order_payments` 和 `order_items` 都可一订单多行。订单级指标分别按 `order_id` 聚合
  后再连接，不能直接连接两张明细表后求和，也不能靠 `SUM(DISTINCT 金额)` 修复重复。
- 商品或卖家维度保留明细金额；若要分配订单支付金额，需先获得明确分摊口径。
  同一订单可跨品类、跨卖家，各组去重订单数之和不必等于全局订单数。

## 需要明确的指标口径

分析前确定纳入的订单状态、事件时间字段、时间范围和金额含义。下表区分候选指标，
并非预设用户想要哪一种；会改变结论的未决定义按主 Skill 返回 `needs_input`。

| 指标 | 计算含义与限制 |
| --- | --- |
| 订单数 | 所选状态和时间范围内的不同 `order_id`；无明细订单是否纳入须明确 |
| 商品金额 | 所选订单对应明细的 `SUM(price)`，不含单列运费；命名 GMV 时声明该口径 |
| 运费金额 | 同一分析范围内的 `SUM(freight_value)`；与配送关系的分析见履约参考 |
| 支付金额 | 先按订单汇总 `SUM(payment_value)`；不能再叠加商品金额和运费 |
| 客单价 | 选定金额总和除以同口径订单数；分母为零时返回无定义，不能记为零 |
| 商品件数 | 核验明细一行一件后计明细行数；`order_item_id` 是序号，不是数量 |
| 购买人数 | 将所选订单关联到客户后计不同 `customer_unique_id` |

商品金额、支付金额、平台佣金和会计收入不是同一概念。金额单位、币种以及税费含义以
数据库说明和可核实的数据来源为准；本样本不能计算真实利润或毛利率。

## 消费者经营

- **复购比例**：先以 `customer_unique_id` 汇总不同订单。区分“窗口内至少两单的消费者
  占窗口购买人数”和“首购后指定天数内再次购买的消费者比例”，两者不能互换。
- **首购群组与留存**：首购是样本内首次观测购买，不保证为真实首次购买。按首购月份
  或其他约定周期分组时，只比较已具有相同后续观测长度的群组；末尾未成熟群组单列。
- **RFM**：R 的基准日使用声明的数据观测截止日，不能用运行当天减去历史订单日期；
  F 计不同订单，M 沿用所选金额口径。打分、分位数和分群阈值需说明；大量并列值或
  低频客户可能使分位分组失效，不强行给每组贴上确定的业务标签。
- **跟进名单**：输出匿名 `customer_unique_id`、分群依据和样本内行为证据即可。
  数据不包含可用的电话或邮箱，名单不能直接用于真实触达；样本内不再购买不能断定流失，
  累计消费金额也不是完整生命周期价值。
- **地域**：同一消费者多笔订单的地址可能不同。订单地域按订单关联地址统计；消费者
  地域分群需约定地址归属，不能把多次地址记录展开后重复数人。

## 商品与支付的易错点

- 产品名称和描述只有长度，无法恢复商品名称、型号或文本主题；品类分析以实际分类字段为准。
- `payment_installments` 是分期期数，`payment_value` 不应再乘它；支付记录序号也不是期数。
- 支付方式占比须说明按记录数、去重订单数还是金额。一个订单可使用多种方式，
  各方式覆盖订单的比例之和可能超过 100%；订单分期分布也不能随意挑其中一条记录代表订单。
- 分析金额差异时，按订单对比商品金额加运费与支付金额，报告差异规模和关联缺失。
  缺少退款流水、优惠及会计明细，不能仅凭差额推断退款、坏账或利润。

## 针对本主题的验证与边界

- 对照订单主表与聚合结果的订单数，分开报告无商品明细、无支付或无客户匹配的记录；
  NULL 是否按零处理应有业务依据，不能为对齐总数擅自补零。
- 对比连接前后商品金额、运费和支付金额，分品类或卖家合计金额应能回到相同筛选下的总额。
- 月度增长与群组比较先识别不完整月份、不同观测长度和少量样本，不能将截断尾部解释为经营下滑。
- 支持历史样本中的销售结构与关联分析；缺少曝光、访问、加购数据，不能构造完整消费者购买漏斗，
  也不能据此证明某种支付方式、品类或营销动作导致消费增长。
