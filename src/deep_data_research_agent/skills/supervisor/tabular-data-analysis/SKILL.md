# 本地表格数据分析

按以下流程规划并执行；根据真实数据和用户目标选择方法，不在本 Skill 中假定业务指标。

## 阶段一：理解任务并规划

1. ①用 `ls /workspace/input/` 核对已上传文件，确认分析目标、指标口径、时间范围、分组维度和期望产物。
2. ②复杂任务用 `write_todos` 建立“探查、分析、验证、输出”计划；简单查询也要先确认输入文件和目标字段。
3. ③缺少会影响正确性的字段、单位、币种、工作表、表头或关联键时调用 `ask_user`，一次最多询问三个问题。

## 阶段二：确定性探查

1. ①逐个执行：
   `python /skills/supervisor/tabular-data-analysis/scripts/profile_table.py --input <上传路径> --output /workspace/profile/<文件名>.json`
2. ②只读取 profile JSON，不把完整表格读入模型消息；关注编码、工作表、表头、字段类型、缺失、重复、范围、公式和截断警告。
3. ③多表关联键、单位或表头仍不明确时先询问，不能根据相似列名直接猜测。

## 阶段三：制定并执行分析

1. ①按任务规模选择工具：常规表格使用 pandas/openpyxl，大表或 SQL 聚合使用 Polars/DuckDB。
2. ②明确输入、清洗规则、指标公式、关联关系、验证方法和输出文件，再编写本次任务专用的 `/workspace/scripts/analyze_<task>.py`。
3. ③原始 `/workspace/input/` 只读，所有中间结果和最终产物写入 `/workspace/output/`；不得运行时安装依赖。
4. ④执行脚本，根据真实报错读取并修正任务脚本；不得隐藏失败、伪造结果或把异常当作空数据。

## 阶段四：验证与输出

1. ①核对输入输出行数、筛选与去重影响、关联未匹配数、分组汇总与总计、单位币种、缺失值和异常值。
2. ②验证失败时先修正；无法消除的限制必须写入结论，不得给出确定性排名或精确结论。
3. ③简单问题直接回答并说明口径；复杂任务按需生成 `analysis_summary.json`、清洗后 CSV/XLSX、PNG 图表和 `/workspace/output/final_report.md`。
4. ④最终回答先给 3–5 条结论，再列出实际产物路径；用户要求下载时调用 `request_report_download` 并传入真实输出路径。

## 注意事项

- 本地文件任务由 Supervisor 同步处理，不启动 crawl-worker；只有用户明确要求网页补充数据时才启动，并区分上传数据与网页证据。
- 不静默填充、删行、去重、类型转换或猜测关联键；所有会影响结论的处理必须说明并验证。
- Excel 公式只读取已有缓存值；缓存缺失时报告限制，绝不执行公式、宏、外部链接或嵌入对象。
- 探查最多扫描每张表 100,000 行；`truncated=true` 只限制探查，正式任务脚本仍应按需求处理完整数据。
- 标识符按字符串处理并保留前导零；不要把订单号、物料号、手机号等当数值计算。
- 业务规则以用户任务和领域 Skill 为准，不在此处写死销售、采购或财务指标。
